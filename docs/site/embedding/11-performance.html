    Performance Notes​

    How fast JaiScript is, what fast script looks like, and how to measure it. This is the one page on the site that holds benchmark numbers.

    Read ratios within one table, never across tables. Every comparison with another runtime was measured on the reference machine (Core Ultra 9 285HX, MSVC x64 Release with LTCG, pinned to one P core). The embedder cost tables were measured on the report machine, a 2016-era 4-core/8-thread laptop, with a different build of the VM. The reference machine runs everything several times faster.

    Kernels and microbenchmarks​

    The kernel suite. Over the sixteen interpreter kernels of daScript's dasProfile, run under its protocol (one process per sample repeating the kernel for 0.5 s, median of five, implementations interleaved, checksums equal), idiomatic typed JaiScript takes a geometric mean of 1.09× Lua 5.5.1's time, and the same algorithms with var everywhere 1.35× (measured 2026-11-12 with every sample pinned to one P core; the four noisiest kernels took ten samples; LuaJIT's row, 2026-11-04).

    LuaJIT's JIT generates machine code at run time, which some shipping targets (iOS) forbid: it is a ceiling, not a target. Style is nearly free: a flat rewrite of GLOOM in free functions and globals produces identical hashes and runs within 2% of the class-based version, so choose the architecture you want to maintain.

    Patterns that matter​

    jaiscript
    // The fast shape: typed locals, typed arrays, & params, compound element stores.
array<int> pix = [];
for (int i = 0; i < 64; ++i) { pix.push(0); }

function shade(array<int>& dst, int base) {      // & = no copy, writes land in the caller
    for (int i = 0; i < dst.size(); ++i) {
        dst[i] += base + (i & 7);                // compound element store: one fused op
    }
}

shade(pix, 100);
int sum = 0;
for (int i = 0; i < pix.size(); ++i) { sum += pix[i]; }
print("sum = {}", sum);

function square(int x) { return x * x; }
array<int> nums = [];
for (int i = 1; i <= 8; ++i) { nums.push(i); }
var squares = parallel_transform(nums, square);   // deterministic at any worker count
print(to_json(squares));
    output
    sum = 6624
[1,4,9,16,25,36,49,64]

    In priority order:

    1. Declare types. int, float and auto locals take the typed fast paths; var is the dynamic opt-out and costs accordingly (1.09× against 1.35× Lua on the kernel suite).
    2. Pass and hold anything heavy by &. Assignment and by-value parameters copy, as in C++. A copy that is only read binds in place for free, but treat that as a bonus (Value Semantics). Walk containers with for (auto& u : units).
    3. Use array<int> and array<float> for bulk numeric data. Same API, raw primitive storage: a 13,600-element grid takes 109 KB instead of 435 KB, a copy is a memcpy, and element access skips boxing.
    4. Write compound element stores. a[i] += v is one instruction, cheaper than the spelled-out read and write.
    5. Keep calls out of the innermost loop. A call costs about ten fused loop iterations. A self tail call (return f(args)) is the exception: it reuses the frame (about 40 ns a call) and runs at any depth.
    6. Parallelize the bulk stages. parallel_for and parallel_transform run bodies the engine proves safe on a worker pool, with identical results at any worker count.
    7. Define classes once. Executing a class declaration does redefinition and hot-reload bookkeeping (about 250 µs for a 30-line class script on the report machine). Per-frame scripts call; they do not declare.
    8. Reuse engines. Creating one and registering the stdlib costs hundreds of warm executes.

    Strings need no builder: s += x, s = s + a + "-" + b, template strings and format() append into the string's own buffer, amortized O(1), whether s is a local, a global, a field, an element or a string& parameter.

    The cost model for embedders​

    What an operation costs​

    Report machine, VM, Release. Use the orders of magnitude.

    operationcost
    fused loop iterationabout 45 ns (about 9 ns on the reference machine)
    script function call in a tight loop0.44 µs; a method call about 1 µs
    warm execute of a repeated one-line string0.60 µs (0.38 µs as a jaibite)
    warm execute of a string never seen before, one line8.4 µs: parse 3.8 µs, compile about 1.5 µs
    warm execute of a 6-line function script, as a jaibite1.69 µs
    30-line class-and-loop script, warmabout 241 µs, nearly all class redefinition
    engine creation plus first trivial executeabout 90 µs
    stdlib registrationabout 311 µs

    Compilation costs about a third of parsing and is cached with the parsed source, so a repeated script pays both once. The automatic jaibite disk cache makes file loads IO-bound: a 535-line game file's load-and-run drops from 5.8 ms to 2.4 ms.

    What each aliasing strategy costs​

    One computation over a mid-sized object (a string, an 8-int array, 4 scalars), VM, µs per call, report machine:

    strategyµs/callagainst &
    read-only, Creature c by value6.61.4×: the copy, about 1.8 µs here, grows with the payload
    read-only, Creature& c4.81.0
    read-only, shared_ptr<Creature> c4.9tie
    mutate through Unit& or shared_ptr<Unit>1.4tie
    method call on a value, an auto& or a shared_ptr4.7tie: the holder does not matter

    On the 15-node BST, & parameters run 1.35× faster than returning and reassigning a shared_ptr, and both about 3.5× faster than by value.

    What the debugger costs​

    The 1000-iteration hot loop, VM, report machine, µs per run:

    configurationµs
    no debugger constructed47
    controller constructed, no session46
    session armed, no breakpoints50
    session armed, breakpoint in a cold file51
    session armed, breakpoint in another file on the hot statement's line number64

    The debugger is free until a session arms, then costs about 10%. The last row is the worst case: one string compare per line-number collision.

    Measuring yourself​

    1. Release only. A Debug build of the engine runs script 25 to 40 times slower.
    2. Pin to one core, interleave the builds you compare, take the median of five or more, and check that every run prints the same result hash.
    3. Time the workload inside the script after a warm-up, so start-up and compilation stay out.
    4. Distrust small deltas. A change smaller than a relink's spread (2% on most programs) is code layout.

    jaiscript_tests "Performance Benchmarks" --verboseJaiScript's own microbenchmarks, in whole µs. Configure with -DJAISCRIPT_ENABLE_BENCHMARKS=ON (docs/BUILD.md).
