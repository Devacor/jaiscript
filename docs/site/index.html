One declaration, no glue

Bind a class once: scripts use it, saves store it, the editor reflects it.

C++
class Spawner : public jai::property_owner<Spawner> {
public:
    JAI_PROPERTY((std::string), id, "north-gate");   // scripted and saved
    JAI_PROPERTY((int64_t), level, 1);
    JAI_SIGNAL(void(int64_t), onWave);               // script-connectable, saved too
    JAI_METHOD(void, spawn_wave, ()) { spawn_wave(level, false); }
    JAI_METHOD(void, spawn_wave, (int64_t size, bool elite)) { level = size; onWaveSignal(elite ? size * 2 : size); }
};
C++ · the host, the same in both tabs
int main() {
    auto engine = jai::engine::make();
    jai::bind_registrar(engine);   // every property_owner and registrar in the program
    auto gate = engine->execute<std::shared_ptr<Spawner>>(R"(
        Spawner gate;
        gate.onWave.connect("hud", [](int size) { print("wave of ", size); });
        gate.level = 3;
        gate.spawn_wave();
        gate.spawn_wave(4, true);
        gate
    )");
    gate->spawn_wave(5, false);     // Emits and is caught by the script-bound lambda

    //Serialization Example:
    std::string spawnerJson = jai::to_json(engine, *gate);
    Spawner roundTrip = jai::from_json<Spawner>(engine, spawnerJson);
    std::cout << "Wave Level: " << roundTrip.level << "\nContents:\n" << spawnerJson << "\n";
    return 0;
}

Each JAI_PROPERTY is the field, its script binding, its save key and its reflection; each JAI_METHOD is the member function and its script binding. No registrar, no glue, nothing to drift.

C++
// spawner.h belongs to another module: you bind it without editing it
class Spawner {
public:
    std::string id = "north-gate";
    int64_t level = 1;
    jai::signal_emitter<void(int64_t)> onWave;
    void spawn_wave() { spawn_wave(level, false); }
    void spawn_wave(int64_t size, bool elite) { level = size; onWave(elite ? size * 2 : size); }
};

// your binding file
static jai::registrar<Spawner, void> spawnerBinding("Spawner", [](jai::dynamic_binder<Spawner>& b) {
    b.property("id", &Spawner::id)          // scripted and saved
     .property("level", &Spawner::level)
     .property("onWave", &Spawner::onWave)  // script-connectable, saved too
     .method("spawn_wave", jai::overload<>(&Spawner::spawn_wave))
     .method("spawn_wave", jai::overload<int64_t, bool>(&Spawner::spawn_wave));
});

Third-party and engine types bind from the outside: the same names reach script, and saves are keyed by the property names.

Either way, the script is the same five lines and sees the same native class, C++ gets the script's own object back, and the same object saves to JSON or binary. The Dynamic Binder walks a class through being scripted, reflected, serialized and hot-reloaded with its state intact.

Two lines to hello

C++
auto e = jai::engine::make();
e->execute("print(\"hello\");");

A static library plus headers, with no global state. jai::stdlib::register_all(e); adds formatted print, math, containers and JSON; every sample on this site assumes it.

jaiscript
var anything = 5;            // dynamic — the explicit, visible opt-out
anything = "now a string";   // fine; you asked for this

class Hero {
    int hp = 10;
    void heal(int amount) { hp += amount; }
}
void bump(int& x) { x += 1; }       // mutation is visible at both ends

auto h = Hero();
h.heal(5);
bump(h.hp);            // fields and elements bind by reference too
print("hp = {}", h.hp);
output
hp = 16

No host yet? Save it as hello.jai and run jaiscript hello.jai. jaiscript alone is a REPL, and --watch re-runs on every save (the runner, its flags). For the web, jai_spider app.jai serves the app over HTTP and applies each saved edit to the next request.

Get JaiScript

git, CMake 3.25+ and a C++20 compiler: Visual Studio 2022 or newer with the C++ workload, the Xcode command line tools, or GCC 11 / Clang 14. CI runs the suites on Windows, Linux and macOS; a gate cross-compiles the library and suites for Android; and the engine runs in your browser as WebAssembly on the Play page.

It clones JaiScript, builds the runner in Release and puts it on your PATH; run it again to update. Then open a new terminal and run jaiscript --version.

What the installer does, its options, and fixing your PATH

Read the scripts before you run them: install.sh, install.ps1 and install.cmd. Not sure which Windows shell you have? PowerShell's prompt shows PS C:\; CMD's shows C:\. The installer also prints the line that starts Gator Quest, an open-world terminal RPG written in JaiScript.

  • They install to ~/.jaiscript, or %LOCALAPPDATA%\jaiscript on Windows. Options pick the folder, a release, a compiler or a generator.
  • --no-modify-path leaves your PATH alone: curl -fsSL https://jaiscript.com/install.sh | sh -s -- --no-modify-path.
  • None of them asks for sudo or administrator rights.

Fix your PATH

If jaiscript --version isn't found, the install folder isn't on your PATH yet:

SystemAdd the runner's folder to your PATH
macOS, Linux, WSLAdd export PATH="$HOME/.jaiscript/bin:$PATH" to ~/.zshrc, ~/.bashrc or ~/.profile, whichever your shell reads, then open a new terminal.
WindowsOpen Start, search for environment variables, choose Edit environment variables for your account, select Path, then Edit, New, and enter %LOCALAPPDATA%\jaiscript\bin. Then open a new terminal.

Seven pillars

01Zero-code binding

One JAI_PROPERTY or JAI_METHOD, or one binder chain for a class you don't own, makes a field scripted, saved and reflected and a method callable.

The Dynamic Binder →

02Hot reload that keeps the world

Edit a class mid-game and live instances migrate with their fields. An edit that doesn't check is rejected, and the old code keeps running.

Hot Reload →

03C++ semantics, all the way down

Assignment copies, T& aliases, and a destructor runs when its value dies. Data changes only where a signature says &.

Value Semantics →

04Typesafe with an escape hatch

int is enforced, auto inferred then enforced, var dynamic. The checker reads the whole program before a line runs.

The Type Ladder →

05Parallel loops that can't race

parallel_for proves each body touches only its own element, then uses every core and gives the same answer at any worker count.

Parallel →

06Safe to embed

No global state, so engines run side by side on threads. Scripts reach only what you bind, under a time budget and an optional memory cap.

Safety Rails →

07Debug it like C++

Breakpoints, stepping and locals in VS Code, attached to a running host; completion and diagnostics from the language server.

Coming from another language

Language Bridges set JavaScript, C++ and C# beside JaiScript idiom by idiom. Code Migrations convert real code off Cereal, Boost.Serialization, Boost.Signals2, ChaiScript, sol2, Squirrel, pybind11, nlohmann::json, Qt properties, RTTR or a coroutine scheduler.

Against the others, on the Performance page: ChaiScript 6.1 takes 23 to 137 times the VM's time on whole programs, and 124 to 1,750 times on recursive calls, a gap that widens as the run grows. Squirrel 3.2 runs 1.2 to 2.2 times faster than the VM on most whole programs; the VM is 1.5 times faster on GLOOM's reference look and 1.8 times faster on a bytecode interpreter written in script. On one core the VM takes 1.09 times Lua 5.5.1's time on average over sixteen kernels and 0.86 to 4.9 times Lua 5.4's on whole programs. Its parallel loops change that where a program has them: on eight cores the demoreel's raymarched OSSUARY runs in 0.40 of Lua's time.

Who it's for

Anyone embedding scripting in a C++ engine who wants hot reload and script classes, safety rails a host tightens in a few calls, types that scale from var to strictly checked int within the same file, and behavior enforced by two implementations arguing with each other.

Built alongside a real 2D game engine, hardened by adversarial review and differential fuzzing, and dogfooded on real, playable things. The source is MIT-licensed; Stability lists what is settled before 1.0. Shipping with JaiScript inside? “Scripted with JaiScript” in your credits would be lovely to see: a request, not a condition.
