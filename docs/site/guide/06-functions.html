    Functions & Lambdas​

    A function is a value: store it, pass it, return it. The rules that govern the chapter:

    • A function is declared in C++'s shape (int f(int a)) or JavaScript's (function f(a)). The language blends the two on purpose, and the spellings mean the same.
    • A typed parameter or return is a typed slot: it converts or rejects exactly as a declaration of that type does.
    • The checker checks every call it can resolve at load, a call through a function<R(A...)> slot included. A call through a bare function or a var is checked when it runs.
    • A lambda's capture list says what it captures: [x] copies, [&x] shares. Arrow functions and function(...) expressions share everything, as [&] does.
    • Functions of one name with different parameter lists overload.

    Declaration forms​

    JaiScript blends C++ and JavaScript, so most things about a function have a spelling from each. The two spellings in a row mean the same thing and mix freely; a type, where one is written, is enforced.

    One behavioral difference: a lambda captures only what its list names ([] captures nothing, [x] copies x, [&x] shares it), while an arrow function or a function(...) expression captures every local it uses by reference, as a [&] lambda does.

    A parameter may also be auto x (locked to its argument's type), and a bare -> before the { infers the return type.

    jaiscript
    int twice(int v) { return v * 2; }

void hello(string who) { print("hello ", who); }

auto square = [](int v) -> int { return v * v; };
auto half = (int v) => v / 2;
var negate = function(int v) { return -v; };
class Counter {
    int n = 0;
    int add(int by) { n += by; return n; }
    function clear() { n = 0; }
    static int limit() { return 100; }
}
coroutine int countdown(int from) { for (int i = from; i > 0; i--) { yield i; } }

for (auto v : countdown(3)) { print(v); }
auto ops = {"double": (x) => x * 2, "square": square};      // functions are values
print(ops["double"](7), " ", ops["square"](3));

    • A method is not read as a value by writing obj.method; use reflect::bind(obj, "method") or a lambda (Classes).
    • A constructor initializer list (: super(...), : this(...)) on anything but a constructor is a parse error: constructor initializer lists (': super(...)' / ': this(...)') are only allowed on constructors.
    • A script function has a fixed parameter count, plus defaults. Variadic functions such as print come from the host (below).

    Return types​

    CaseResult

    Parameters and defaults​

    ParameterMeaning
    int xtyped: converts its argument as int x = argument; would (a float or a string is rejected, and so is a number into a string parameter)
    x, var xdynamic: a var local initialized from the argument
    auto x, :xlocked to the argument's type, as auto locks to its initializer's
    int: nshorthand for int n
    int& x, var& x, Creature& cbinds the caller's variable. A literal or temporary binds only when the function never writes through the parameter (Value Semantics).
    int x = 2a default; every parameter after it needs one too

    A by-value parameter holds a copy of its argument, and a by-value return hands out a copy. A class instance or a bound C++ object is copied, so writes stay in the callee; a handle (new T(), a shared_ptr<T>) is copied and shares its object. To write into the caller's object, take it by reference. A T& return names storage the same way: a field, an element, a global, or a local of the function, which it shares as a [&] capture does, so the caller's reference keeps the local alive (what a reference keeps alive). A shared_ptr<T> parameter or return takes a handle, never a T value: make_shared<T>(value) copies one into a new handle.

    Defaults work on functions, lambdas, methods, static methods, constructors and namespace functions. A default is evaluated at each call that leaves it out, and binds as the argument it stands in for:

    • A by-value default converts like an argument: float p = 2 holds 2.0.
    • A reference default names storage: int& p = total writes total, and int& p = 5 is the load error cannot bind non-lvalue default to reference parameter 'p'. const int& p = 5 binds a temporary.
    • A default cannot name another parameter. function f(a, b = a * 2) is the load error default value of 'b' names parameter 'a': a default cannot read a parameter. Compute such a value in the body.
    jaiscript
    function greet(name, string greeting = "hello") { return greeting + " " + name; }
int square(int: n) { return n * n; }
auto id = [](:x) -> { return x; };
void heal(int& hp, int amount = 25) { hp += amount; }
int health = 50;
heal(health);
print(greet("world"), " / ", greet("world", "salve"), " / ", square(6), " / ", id("same"), " / ", health);
    output
    hello world / salve world / 36 / same / 75

    Calls: what is checked, and when​

    A call to a function the program declares is resolved at load: the argument count (defaults included) and each argument against its parameter. Every such error in a file is listed at once:

    jaiscript
    int fib(int n) { return n < 2 ? n : fib(n - 1) + fib(n - 2); }
print(fib(10, 2));
print(fib("ten"));
    output
    jaiscript: static check failed:
<script>:2:16: error: 'fib' expects 1 argument(s), got 2 (declared at 1:5)
    print(fib(10, 2));
                   ^
<script>:3:16: error: argument 1 of 'fib': cannot pass 'string' to 'n' declared 'int' (declared at 1:5)
    print(fib("ten"));
                   ^
    • Through a function<R(A...)> slot the same mistakes fail the load (Signatures). Through a bare function or a var they are run-time errors, and catchable: 'fib' expects 1 argument, got 2, Cannot pass string to parameter 'n' of 'fib' (declared int).
    • A var argument to a direct call is converted when the call runs, and raises there if it does not fit.
    • A reference parameter takes a variable of its type (cannot bind 'float' to 'x' declared 'int&'), or a literal when the callee never writes through it ('f' writes through parameter 'x' (line 1); pass a variable).
    • A call to an overloaded name is an error only when no overload fits.
    • Host (C++) functions are checked for argument count and for the certain cases (Static Checking). Chapter 13 lists everything the checker sees.

    A call evaluates its callee first, then its arguments left to right, and each by-value argument takes its value as it is evaluated (Evaluation order): f(swap()) calls the f held before swap() replaced it. The rule covers functions, lambdas, methods, constructors and new, and adds:

    • A conversion the binding runs for one parameter, such as a converting constructor, runs after every argument has been taken.
    • A constructor takes its arguments before its field initializers and initializer list run.
    • A coroutine takes its arguments at the call and binds them at its first next().
    • A host function receives scalars, strings and elements by value the same way. An instance, array or map argument reaches it as the object named: a C++ T& parameter works on that object, and a by-value C++ parameter copies it when the function is entered.

    Every call is also a point where the execution budget is checked.

    [[nodiscard]]: a result the caller must use​

    [[nodiscard]] before a function, a method (static too), a coroutine or a namespace member makes a statement that drops its result a load error, as it does either arm of a conditional written as a statement. Keep a result you do not want in the placeholder _:

    jaiscript
    [[nodiscard]] int checked_add(int a, int b) { return a + b; }
class Wallet {
    int gold = 3;
    [[nodiscard]] bool spend(int n) {
        if (n > gold) { return false; }
        gold -= n;
        return true;
    }
}
Wallet w;
auto paid = w.spend(5);          // kept
auto _ = w.spend(1);             // dropped on purpose
auto _ = w.spend(1);             // _ is declared again freely
print(checked_add(2, 3), " ", paid, " ", w.gold);
    output
    5 false 1

    A dropped result fails the load: the result of 'checked_add' is discarded, but 'checked_add' is [[nodiscard]]: use it, or keep it in the placeholder (auto _ = checked_add(...);).

    • Where it is checked. At every call the checker resolves at load: a function of the program, a method of a class it knows, a namespace member, a builtin, and a host function or bound method registered with jai::nodiscard (Host API). A call through a function value or a var receiver is not checked, at load or at run time. A call to an overloaded name fails when every overload it can reach is [[nodiscard]]. A program's last expression is the value of execute(), so it is not discarded.
    • Where it may be written. Anywhere else it is a parse error ([[nodiscard]] applies to a function or a method), and so is a void function ([[nodiscard]] function 'f' returns void: there is no result to keep).
    • The placeholder. There is no cast to void; auto _ = f(); is the spelling. As in C++26, a local or a structured binding named _ may be declared any number of times in a scope, each living to the scope's end. Once a scope declares more than one, naming _ is a load error ('_' is declared more than once in this scope, so it names none of them: give the variable you use its own name). A single _ is an ordinary variable, and a parameter list declares _ once.
    • The library's copying functions are [[nodiscard]]: string::to_lower, to_upper, trim, replace, repeat, pad_left, pad_right, append; array::append, concat, slice, filter, map, sort, reverse; map::filter. The error names the in-place method: the result of 'string::to_upper' is discarded: it returns a new value and leaves its argument unchanged, so the statement does nothing; keep the result, or call the in-place method (name.to_upper(...)).

    Returning nothing: a result that is not there​

    A callee declared to return nothing has no result, so a call whose result is used fails the load: an initializer (var and auto included), an assignment, an argument, the return value of a function or lambda declared or known to return a value, an operand, a string interpolation or a template splice. A statement, a for's update and the arms of a conditional written as a statement discard a result, and so does a return in a body that declares no value (void, auto or no type spelled, an arrow's one expression included; var declares one): there return f(); returns nothing, as C++ allows it for forwarding and early exits (void g() { return f(); }, if (!ok) { return f(); }). A deduced body (an auto function or method, a lambda with no result type) none of whose returns gives a value is itself a callee that returns nothing (one every path of which throws is not: it never returns), by name, as a static method, as a generic function's instance, and through a variable declared from the lambda: auto dbl = () => xs.map(x => x * 2); print(dbl()); gives the result of 'dbl' is used, but 'dbl' returns nothing: map changes xs in place and returns nothing; array::map(xs, f) returns a mapped copy, naming the builtin's copying twin when the nothing came from one. A return that gives a value makes the body declare one, so its other returns of nothing are uses, as C++ deduces no result from both (auto pick(bool p) { if (p) { return a(); } return 3; }). It is the [[nodiscard]] rule turned around, and it holds for every callee the checker resolves at load: a function, a static method or a namespace member declared void, each instance of a generic function declared void, a function<void(...)> signature, a builtin method that changes its receiver in place, and a host function whose C++ result is void. A method of a class is not one: it dispatches on the object, and a subclass may override it to return a value.

    jaiscript
    class Meter {
    int level = 0;
    void add(int n) { level += n; }
    static Meter add(Meter m, int n) {
        Meter copy = m;
        copy.add(n);
        return copy;
    }
}
void say(string text) { print("say: ", text); }
Meter m;
m.add(2);                        // a statement: m changes
Meter more = Meter::add(m, 3);   // the copying twin returns a new Meter
say(`${m.level} ${more.level}`);
    output
    say: 2 5
    • The text. var shown = say("hi"); fails the load with the result of 'say' is used, but 'say' returns nothing: call it as a statement. A static method is named with its class ('C.reset'), a namespace member with its namespace ('tools::ping'), an instance with its type arguments ('gen<int>'). int x = say("hi"); is that one error, not a second one about null.
    • Methods. A call of a class's method, a bound host method included, is never checked: the call dispatches on the object, so a subclass's override, a script class's over a bound class among them, may return a value where the class the call is written against returns nothing (c.m() through a C& holding a D whose m returns 4 gives 4). A method that ends without returning a value gives null where its result is read, as a function does: var r = c.m(); leaves r null. A method with no result spelled that returns a builtin in-place call (auto sorted() { return xs.sort(); }) still fails the load at that return, used or not, with the builtin's text and twin (declare the method void to forward the call).
    • A lambda that returns nothing. x => ys.push(x) and [&](int x) { return ys.push(x); } are lambdas that return nothing, as a C++ lambda whose body calls a void function is: xs.for_each(x => ys.push(x));, an event handler and a function<void(int)> slot take it. Where the checker knows the lambda's result is needed, it fails the load: a builtin that reads its callback's result (map, filter, sort, reduce, find, find_index, some, every, remove_if, as methods and as array:: and map:: functions, and the engine's parallel_transform and parallel_reduce, whose step may instead take its accumulator by reference and return nothing) gives the lambda returns nothing, but array::map needs a value from it, and so does a lambda whose returns give no value or a function declared void passed there ('take' returns nothing, but filter needs a bool from it). A signature that returns a value gives 'lambda' declared to return 'int' returns no value here, and a function declared to return a value gives the call's own error (int g() { return f(); }). Where the load cannot see the callback's target, the lambda's null goes through: the check covers the builtin container methods, the engine's parallel forms and signatures, and a host function's callback only where its C++ parameter is a typed std::function.
    • A name that may be rebound. A function's name or a lambda variable is a known callee only while nothing can rebind it, for the whole unit: once it is assigned anywhere, or passed as an argument to anything but the library's value-taking forms (array::, map::, parallel_transform, parallel_reduce), where a reference parameter could rebind it, its calls are not checked. The test is by name, so a parameter or local of the same name passed anywhere does the same.
    • What is not checked. A method's call (above). A call the load cannot resolve: a function value without a signature (var g = say;), a var receiver, an overloaded name one of whose reachable overloads returns something. A deduced body is known only along the routes above: a lambda that travels through a parameter, a container, a field or another function's result, and a deduced function called from a body the load reads before the function's own, return what they return without a load error. An arrow whose untyped parameter is the receiver of an in-place method (a => a.sort(), ls.for_each(l => l.sort())) gives up that method's run-time error. Such a call gives null when it runs. A builtin method on a var receiver is the exception: its error is raised when the call runs, before anything changes.
    • The program's last expression is the value of execute(), so say("hi") ending a program is not a use.

    Type arguments: a type a host function takes​

    A call may name types before its arguments: from_json<Pet>(text), db.query<User>(sql, id). Each type argument reaches the callee as a value, ahead of the others: f<T1, T2>(a, b) calls f(T1, T2, a, b), where each type is a reflect::type (Reflection). Only a host function or bound method takes one, and the host decides what it means: the library's from_json<T> builds a T from a JSON document, and from_binary<T> builds one by the same rules from to_binary's bytes. A class is built with T() and each field filled by name; a key the class has no field for is skipped, and a field no key names keeps its initializer. An object written with its $type, as to_json writes one, loads as the class it names and is held to the same rule: a value one of its fields cannot take fails the load (from_json: field 'age' of 'Pet' is int, not string), where from_json(text) would keep the field's constructed value (Serialization). A $type that names no class of the program fails where a class belongs: from_json: the JSON is Pat, not Pet.

    jaiscript
    class Pet {
    string name;
    int age = 1;
    array<string> tricks;
}
Pet rex = from_json<Pet>("{\"name\": \"rex\", \"tricks\": [\"sit\"], \"owner\": \"max\"}");
auto pack = from_json<array<Pet>>("[{\"name\": \"kit\", \"age\": 3}, {\"name\": \"ash\"}]");
print(rex.name, " ", rex.age, " ", rex.tricks[0]);
print(pack.size(), " ", pack[0].name, " ", pack[1].age);
    output
    rex 1 sit
2 kit 1
    • Typed results. A host registration may declare its result in terms of the first type argument: T, array<T> or shared_ptr<T> (Host API). The checker then types the call, so auto pack above is an array<Pet> and pack[0].nmae is a load error (no member 'nmae' in class 'Pet').
    • What a type argument may be. Any type a declaration spells: int, a class, shop::Product, array<T>, map<K, V>, shared_ptr<T>. A name that is no type is the declaration's error, unknown type 'Nope'. A class is named, not captured: the host builds the class loaded when it builds, so hot reload applies.
    • A script function takes them only as a generic. A function, method or class that declares type parameters is a generic: largest<int>(xs) calls its instance, and nothing is passed at run time. On any other script function, method or local lambda, f<int>(1) is a load error: 'f' takes no type arguments: it is not a generic function. A type that takes none, named with them (Hero<int>()), says what the name is: 'Hero' takes no type arguments: it is not a generic class. JaiScript has no templates of its own; a script function that wants a type takes a var.
    • The callee. A name (f), a member (a.f, a->f) or a namespace member (ns::f) followed by <.
    • Reading <. Type arguments need something declared at load that takes them. < after a name opens type arguments only when what follows is types up to a closing > (a >> closes two) that (, { or :: follows, and the name, looked up where it stands, names something declared that is no variable: a generic, a function, a class, a host function or a host template. After a variable it compares: a local, a parameter, a field (own or inherited), a static, an enum value, a namespace's variable or a program-scope one, declared above, below or in another file of the program. A name nothing declares at load compares as well (a variable a computed-path include brings, an execute's instance variable), and the checker reports it when it is never declared. The nearest scope that declares the name decides: in a class with a field id, id < n, m > (k) compares even where a generic id<T> is declared elsewhere. So two(a < b, c > (d)) is two comparisons when a is a variable and one call when a is a generic; (a < b) > (c) compares whatever a is. Two shapes are read before the name is asked. A run that holds a type's keyword (l<int>(2)) and a > before an empty () are spelled by no comparison: they are type arguments, and a callee that takes none is the checker's error. A (...) that => follows is a lambda, so the < before it compares. After a member (p.x <) the receiver's class is not known when the text is read, so the member's name decides: type arguments only when some class declares a generic method of that name or the host binds a method of that name that takes a type. A field named as another class's generic method therefore keeps the type-argument reading: parenthesize the comparison, (p.x < w). Inside a generic, a name that begins with a type parameter (T::make<U>(x)) opens type arguments; a comparison there takes parentheses. Where a call was read on such a member, the member takes no type arguments and one of them names no type, the load error says what was read and what to write: unknown type 'w': 'p.x<w, h>(...)' reads as a call with type arguments, which 'p.x' does not take; if this is a comparison, write (p.x < w). Where a comparison was read and nothing declares the name, the error says which generic is missing: use of undeclared identifier 'mke' (no generic 'mke' is declared: '<' after a name that takes no type arguments compares).

    Function-typed variables and fields​

    function name = expr; declares a variable that holds any function or null, and function name; starts null. It works at top level, in a function body, in a namespace and as a class field. Any other value is rejected, at load (cannot assign 'int' to 'cb' declared 'function') or at the store (Cannot assign int to 'cb' (declared function)). A bare function names no signature, so a call through it is checked when it runs; function<R(A...)> names one (below).

    jaiscript
    function scale = [](int v) { return v * 10; };
function cb;
cb = scale;
class Button { function on_click = []() { return "unbound"; }; }
auto b = Button();
b.on_click = []() { return "clicked!"; };
print(cb(5), " ", b.on_click());
    output
    50 clicked!

    Signatures: function<R(A...)>​

    function<int(int, string)> is the type of a callable that takes an int and a string and returns an int, as std::function spells it. It goes wherever a type does: a local, a field, a static, a parameter, a return, an array element, a map value, a namespace variable, a cast. A parameter is passed by value, or by reference as T&; a name after a parameter's type is allowed and means nothing (function<int(int damage)>). void takes any result and drops it, var as a result or a parameter is dynamic, and function<void()> takes no argument. A slot starts null and resets to null. A signature spells every type: function<auto(int)> is the parse error a function signature declares its result: function<R(A...)>, with void for none and var for any, and an auto parameter is a function signature declares each parameter's type: function<R(A...)>, with var for any.

    jaiscript
    class Hero { string name; int hp; Hero(string n, int h) { name = n; hp = h; } }
int twice(int v) { return v * 2; }

function<int(int)> f = twice;                  // a named function whose declaration fits
function<int(int)> g = x => x + 1;             // x takes int from the signature
array<function<int(int)>> steps = [f, g, x => x * 10];
map<string, function<string(Hero)>> labels = {"name": h => h.name, "hp": h => `${h.hp} hp`};

int run(array<function<int(int)>> fs, int v) {
    for (auto& step : fs) { v = step(v); }
    return v;
}
array<Hero> sort_by(array<Hero> heroes, function<int(Hero)> key) {
    heroes.sort((a, b) => key(a) < key(b));
    return heroes;
}

Hero bo = Hero("Bo", 7);
print(run(steps, 1), " ", labels["name"](bo), " ", labels["hp"](bo));
for (auto h : sort_by([bo, Hero("Al", 3)], h => h.hp)) { print(h.name); }
    output
    30 Bo 7 hp
Al
Bo

    A lambda takes its types from the signature it initializes. An arrow function, a lambda or a function(...) expression written where a signature is expected (a declaration, an assignment, a field initializer, a constructor's member initializer, a return, an argument, an element of a typed array or map literal) types each bare parameter name by the signature, and an undeclared result by the signature's result. Its body is checked with those types: h => h.hpp against function<int(Hero)> is no member 'hpp' in class 'Hero', and a parameter converts its argument as a parameter of that type would. A parameter the lambda types itself ((int x), (var x), (auto x)) keeps its type, and a parameter the signature passes by reference stays a by-value copy unless the lambda writes T&. A host function's std::function<R(A...)> parameter is such a signature (Static Checking). The signature is read from declarations alone: a receiver's flow-narrowed class types no lambda, since a narrowing changes nothing a program runs.

    What a store checks. A callable whose declaration the load sees (a named function, a lambda literal, a static method, a coroutine, another slot's signature) must fit the signature:

    Lambdas and captures​

    Capture lists read as in C++: [] captures nothing, [x] copies, [&x] shares, and naming a local the list does not admit is an error. Three differences: a program-scope variable is never captured (the lambda reads it when it runs, unless the list copies it with [g]); a copied capture is writable and there is no mutable; and a copy of a lambda shares its captured state with the original.

    CaptureWhat the lambda holds
    []nothing. Naming an enclosing local is the parse error lambda capture list does not capture enclosing local 'n'; name it or use [=] or [&].
    [x], [=]its own copy of x (of every local it uses), made when the lambda is made, as auto x = name; copies: a class instance or a bound C++ object is copied, a handle is shared. A C++ class without a copy constructor cannot be copied: share it with [&c].
    [&x], [&]the variable itself. A shared local outlives the function that declared it.
    [x = expr]the lambda's own x, initialized as auto x = expr; when the lambda is made
    [weak_this], in a methoda weak_ptr to the instance, named weak_this, which does not keep it alive (weak_this)
    [g] on a globalthe global's value now. Uncaptured, a global or namespace variable is read when the lambda runs, by every lambda, [] included.
    jaiscript
    int level = 1;                                    // program scope
auto live = []() { return level; };               // read when the lambda runs
auto pinned = [level]() { return level; };        // [g] copies the global now
auto scaled = [k = level * 10]() { return k; };   // init-capture
level = 2;
print(live(), " ", pinned(), " ", scaled());

class Counter { int n = 0; }
function tally() {
    int hits = 0;
    Counter value = Counter();
    auto handle = new Counter();
    auto hit = [&hits]() { hits += 1; };
    auto read = [hits, value, handle]() { return [hits, value.n, handle.n]; };
    hit(); hit();
    value.n = 5;                                  // read holds its own Counter
    handle.n = 5;                                 // and shares this one
    print(hits, " ", read());
}
tally();

function make_counter() {
    int n = 0;
    return [=]() { n += 1; return n; };           // a copied capture is the lambda's own, kept between calls
}
auto next = make_counter();
auto same = next;                                 // a copy of a lambda shares its captures
print(next(), " ", next(), " ", same(), " ", next());
    output
    2 1 10
2 [0, 0, 5]
1 2 3 4
    • A copied capture belongs to the lambda. Its body may write it, and the next call sees the value, as in a C++ mutable lambda. Writing mutable is an error: A lambda takes no 'mutable': its copied captures are already its own, writable and kept between calls.
    • A copy of a lambda is the same closure. auto same = next; is a second name for one set of captures, where C++ would copy them: the counter above counts through both.
    • A copy of a value rebinds the lambdas inside it. A lambda the copied value holds that captured an object the value also holds (or [weak_this] of it) is bound to that object's copy, with its own copies of its by-value captures; its by-reference captures stay shared. A lambda bound to anything outside the value is shared by the copy (Value Semantics).
    • Nested lambdas reach an enclosing function's local through every lambda between them, and each of those must admit the name with a default or named capture, even if it does not use it: [=](int step) { return [=]() { return base + step; }; }. In a method the same holds for the instance: a field or method a nested lambda names by bare name is captured by every lambda around it, so () => { var inner = x => bonus + x; return inner(5); } reads the instance's bonus wherever it is called, and an enclosing [] is the capture-list error.
    • In a method, [this], [=] and [&] capture the instance and reach its fields and methods by bare name, as they are when the lambda runs; [] reaches neither (Name resolution in methods).
    • A named function declared inside a function body captures nothing. It sees the program scope and its own parameters and locals. Naming an enclosing local is a parse error: Nested function 'helper' cannot use enclosing local 'y': a named function captures nothing; use a lambda with a capture ([&], [=] or [y]) or function(...) / =>. A coroutine declared in a function body follows the same rule.
    • Cycles. A reference capture can close a cycle: var again; again = [&]() { again(); };. When the frame exits, a shared local that only its own closures hold is released, and its destructor runs then. A closure that escaped keeps its shared locals while anything holds it; the engine reclaims an abandoned cycle in a later sweep, at the latest when it is destroyed.

    A closure reads a global when it fires. A stored hook or a signal receiver can outlive the file that made it, and a later file or the host may have rebound that global by then. Pass context as a parameter or pin it in the capture list.

    weak_this: a lambda that does not keep its instance​

    A lambda that names a member holds its instance, as a C++ lambda holding shared_from_this() does: the object lives until the lambda is dropped, and an object that stores such a lambda in its own field holds itself. [weak_this] captures a weak_ptr to the instance instead. The body asks weak_this.expired() whether the object is gone and reaches it through weak_this.lock(), which is null once it is.

    jaiscript
    class Button {
    string label = "ok";
    var on_click;
    ~Button() { print("gone: ", label); }
    void wire() {
        on_click = [weak_this]() {                // the button holds the lambda; the lambda does not hold the button
            if (weak_this.expired()) { return "expired"; }
            return weak_this.lock().label;
        };
    }
}
function demo() {
    var click;
    {
        Button b;
        b.wire();
        click = b.on_click;
        print(click());
    }
    print(click());
}
demo();
    output
    ok
gone: ok
expired

    weak_this sits beside other captures ([=, weak_this], [weak_this, &total]). It is the lambda's only route to the instance: a bare member or this in the body still needs [this], [=] or [&], which hold the instance. A lambda nested in a [weak_this] lambda captures the same weak_ptr with its own [weak_this]. Outside a method there is no instance, and [weak_this] is an undeclared name.

    Arrow functions and function expressions​

    (params) => expr, (params) => { body } and function(params) { body } have no capture list: each is a [&] lambda. It reads and writes the locals around it, sees later writes, and keeps those locals alive after the enclosing function returns.

    jaiscript
    auto add = (int a, int b) => a + b;
auto shout = name => string::to_upper(name) + "!";       // one untyped parameter needs no parentheses
function make_account(int opening) {
    int balance = opening;
    var deposit = function(int amount) { balance += amount; return balance; };
    balance += 100;                                       // a later write: the closure sees it
    return [deposit, () => balance];
}
auto account = make_account(10);
print(add(2, 3), " ", shout("ada"), " ", account[0](1), " ", account[1]());
var curried = function(int a) { return function(int b) { return a + b; }; };
array<var> readers = [];
for (int i = 0; i < 3; ++i) { readers.push(() => i); }
print(curried(2)(3), " ", readers[0](), readers[1](), readers[2]());
    output
    5 ADA! 111 111
5 012
    • A loop variable captured by reference is the iteration's own. The variable a C-style for declares is a fresh one each iteration for the closures that share it ([&], [&i], an arrow function, function(...)): its value is copied forward before the update runs, as JavaScript's let and Go do, and a closure that writes it changes the loop only in its own iteration. A variable declared in a loop body and a range-for variable are each iteration's own already.
    • An arrow function's parameters may be typed ((Unit& u) => ...), and it declares no return type: it takes one from the signature it initializes (Signatures). Elsewhere, write a lambda ([&](int x) -> int { ... }) when the type matters, for instance to make array::map return an array<int>.
    • A parenthesized expression stays one: only a ) followed by => makes the group a parameter list.

    Overloads and redefinition​

    C++'s rule: functions of one name with different signatures coexist, a call takes the best match, and a tie is an ambiguous call.

    A signature is the parameter count and each parameter's declared type (an untyped one is var). References and default values are not part of it. Overloading works at program scope, in namespaces, for methods and for constructors. A call takes the best match, in this order:

    1. every argument exact;
    2. fewer and cheaper conversions;
    3. fewer var parameters;
    4. fewer defaults filled in;
    5. the nearest base class.
    jaiscript
    int damage(int a) { return a; }
int damage(int a, int b) { return a + b; }
string damage(string who) { return who + " is hit"; }
class Pawn { } class Gator : Pawn { } class BigGator : Gator { }
string kind(Pawn p) { return "pawn"; }
string kind(Gator g) { return "gator"; }
print(damage(2), " ", damage(2, 3), " ", damage("gator"), " ", kind(BigGator()));
    output
    2 5 gator is hit gator
    SituationResult
    two overloads match a call equally wellAmbiguous call to 'hit' with (int, int): 'hit(int, float)' and 'hit(float, int)' match equally, at load when the checker knows the argument types, else when the call runs
    two definitions differ only in which parameters are referencesan error: 'f(var x)' differs from 'f(var& x)' (line 1) only by reference; overloads must differ in parameter types or count. Ones that also differ in a type (mix(var& r, string s), mix(var r, int n)) coexist.
    the same signature twice in one filea load error, 'damage' is already defined (declared at 1:5); in a [[warn_mode]] region the second definition raises when it runs ('damage(int a)' is already defined (line 1))
    the same signature from another unit: a later execute, another file, a module re-run because its file changedreplaces the earlier one, which is how hot reload swaps a function. A unit that runs again replaces or drops only the overloads it declared itself.
    a function and a coroutine of one namea coroutine does not overload. With different parameter lists they replace each other, with the warning duplicate definition of function 'f' replaces the earlier one (a coroutine does not overload); with the same list it is the redefinition error.
