    Generics​

    A generic is a class, a function or a method with type parameters: class Stack<T>, T largest<T>(array<T> xs). It is declared once and instantiated at load for each list of type arguments the program uses, and each instance is checked and run exactly as if it had been written by hand with the arguments in place of the parameters. This is C++'s template model.

    • Nothing is boxed and no T exists at run time: after the load, Stack<int> is an ordinary class named Stack<int> and largest<int> an ordinary function. Reflection, serialization, the debugger and both backends see ordinary declarations.
    • Type parameters go after the name, in the angle brackets array<T> already uses. template<typename T> is not a second spelling: it fails the load and names this one.
    • A generic's own text is parsed when its file loads, used or not, so a syntax error in it always fails the load. Its types are checked per instance.

    Generic classes​

    class Name<T, ...> declares one. Name<Args> then stands wherever a class name does: a declaration, a parameter, a field, a base class, new Name<Args>(...), Name<Args>(...), Name<Args>{...}, Name<Args>::member, cast<Name<Args>>, dynamic_cast<Name<Args>>, and where a value stands, as a class's name does there: extend(obj, More<int>), and auto make = Pair<string, int>; is its constructor as auto make = Goblin; is a class's. A namespace's generic class takes each form by its qualified name, as a namespace's class does: shop::Shelf<int>(...), shop::Shelf<shop::Item>{...}.

    jaiscript
    class Stack<T> {
    array<T> items;
    void push(T item) { items.push(item); }
    T pop() { T last = items[items.size() - 1]; items.pop(); return last; }
    int size() { return items.size(); }
}

class Pair<K, V> {
    K first;
    V second;
    Pair(K k, V v) { first = k; second = v; }   // the bare class name inside is Pair<K, V>
}

Stack<int> numbers;                      // a type, anywhere a type is written
numbers.push(3);
numbers.push(9);
print(numbers.pop(), " ", numbers.size());

auto hp = Pair<string, int>("hp", 10);   // a construction names the arguments
print(hp.first, " = ", hp.second);
print(reflect::type_of(numbers), " / ", reflect::type_of(hp));
    output
    9 1
hp = 10
Stack<int> / Pair<string, int>
    • The class's bare name inside it is the instance. In Pair<K, V>, Pair alone (its constructor, a return type, a field) is Pair<K, V>; another instance is spelled with its arguments, Pair<V, K>.
    • A generic class is not overloaded. One unit declares a class name once: class Dup<T> beside class Dup<K, V> fails the load with generic class 'Dup' is declared with 1 type parameter on line 1 and with 2 type parameters here: a generic class cannot be overloaded by its parameter count, and so does a class beside a generic class of its name. A later unit's declaration replaces the earlier one (Declaring it again).
    • A class's type arguments are always written. A constructor does not deduce them: Pair("hp", 10) fails the load with 'Pair' is a generic class: its type arguments are written, never deduced from a constructor's (Pair<K, V>(...)).
    • A base may be an instance, of the class's own parameters or of fixed types: class Derived<T> : Base<T>, class Ints : Base<int>; a constructor initializer names it the same way, : Base<T>(x).
    • A generic is declared where it stands, as a class or a function is: top-level code runs in order, and a use of Name<Args> above the generic's declaration is the error a plain name gives, 'Box' is used before its declaration (line 3): top-level code runs in order, so declare it above the use or make the use after it. When an instance is declared has the rule.

    Generic functions​

    A function lists its type parameters after its name, in either head; a coroutine and a namespace's function do the same. A call writes the type arguments, largest<int>(scores), or leaves them to deduction.

    jaiscript
    T largest<T>(array<T> xs) {
    T best = xs[0];
    for (auto x : xs) { if (x > best) { best = x; } }
    return best;
}

function smallest<T>(array<T> xs) -> T {          // the trailing-return head: the same thing
    T best = xs[0];
    for (auto x : xs) { if (x < best) { best = x; } }
    return best;
}

coroutine T each<T>(array<T> xs) { for (auto x : xs) { yield x; } }

array<int> scores = [4, 8, 2];
print(largest<int>(scores), " ", smallest<int>(scores));   // the type argument written
print(largest(scores), " ", largest(["fig", "pear"]));     // or deduced from the argument
int sum = 0;
for (auto v : each(scores)) { sum += v; }
print(sum);
    output
    8 2
8 pear
14
    • Overloads. A generic function may share its name with ordinary functions and with other generics. An ordinary function that takes the call wins over a generic, in whichever unit it is declared: this one, a file the program imports, a unit that ran earlier. A namespace's function and a class's method, static or not, win over a generic of their name the same way. Of the generics, those whose type arguments can be found are the candidates. Candidates that find the same type arguments name one instance, and each is an overload of that name: with string show<T>(array<T> xs) beside string show<T>(T x, int n), show<int> is two functions, show<int>(array<int> xs) and show<int>(int x, int n), and the call's value arguments pick between them as between two functions written by hand, whether its type arguments were written (show<int>(5, 1)) or deduced (show(5, 1)). Two of them of one signature define it twice, as two functions written by hand do: show<T>(T x) beside show<V>(int x) fails the load at show<int> with 'show<int>' is already defined. Candidates that find different type arguments name different instances, and the call fails the load: call to 'show' is ambiguous: the generics 'show<T>' (app.jai:1:6) and 'show<T>' (app.jai:2:6) both take it. Generic methods of one name overload the same way.
    • A generic function is not a value, nor is its instance. function f = largest<int>; fails the load with 'largest<int>' is an instance of the generic function 'largest', which is not a value: call it, or pass a lambda that does ((x) => largest<int>(x)), and the bare name, auto f = largest;, with 'largest' is a generic function, which is not a value: ..., the same advice with its parameters, largest<T>(x). A generic method says the same as 'Cfg::make' is a generic method through its class, and through a receiver 'conv<int>' is an instance of the generic method 'conv', which is not a value: call it, or bind it with reflect::bind(p, "conv<int>"). Pass a lambda that calls it, (xs) => largest<int>(xs).
    • < after a name opens type arguments only where a type-shaped run closes on a > that (, { or :: follows and the name, looked up where it stands, names something declared that is no variable; anywhere else it compares. a < b and both(a < b, c > (d)) on variables read as they always did, whether the variables are locals, fields (own or inherited), statics, enum values or another file's, and largest<Pet>(pets) is a call wherever largest is declared: above, below, in an imported file (Type arguments has the rule in full).

    Deduction​

    A call to a generic function or method may leave out type arguments that its value arguments name. Each parameter whose declared type mentions a type parameter is matched against the argument's load-time type:

    You writeWhat it is
    Tany type: the argument's own (T& deduces as T)
    array<T>, map<K, V>an array or a map of declared element types; a literal of one element type counts ([1, 2] is an array<int>)
    shared_ptr<T>, weak_ptr<T>a handle to a T
    Name<T>an instance of the generic class Name or of the host template Name, or a class that derives from one
    function<U(T)>a function value that declares one signature: a variable declared with a signature, a function's name, a lambda whose parameters declare their types. The result and each parameter are matched in turn
    coroutine<T>a coroutine's handle, by what it yields
    jaiscript
    K first_key<K, V>(map<K, V> m) { for (auto [k, v] : m) { return k; } return K(); }
T unwrap<T>(shared_ptr<T> p) { return p; }
U convert<U, T>(T x) { return cast<U>(x); }
void swap<T>(T& a, T& b) { T t = a; a = b; b = t; }
class Goblin { int gold = 3; }

map<string, int> stock = {"tee": 4};
print(first_key(stock));                    // K = string, V = int, from map<K, V>
shared_ptr<Goblin> g = new Goblin();
print(unwrap(g).gold);                      // T = Goblin, from shared_ptr<T>
print(convert<string>(41) + "!");           // U written, T deduced
int a = 1;
int b = 2;
swap(a, b);                                 // T& deduces as T
print(a, " ", b);
    output
    tee
3
41!
2 1

    The arguments a call writes fill the leading parameters and the rest are deduced, which is why convert lists U first. Deduction never converts: two arguments that give one parameter two types are an error, not a promotion. A null says nothing of a type and is skipped. A function value is read only through a signature: against function<U(T)> the signature it declares is matched, and a variable declared with a signature has that type wherever it is passed (T takes it as it stands). A lambda's result is the one it declares, else the one type its returns yield.

    jaiscript
    array<U> map_all<T, U>(array<T> xs, function<U(T)> f) {
    array<U> out;
    for (auto x : xs) { out.push(f(x)); }
    return out;
}
int twice(int n) { return n * 2; }
function<string(int)> label = (int n) => "#" + to_string(n);

print(map_all([1, 2, 3], twice));                // T = int and U = int, from twice's declaration
print(map_all([1, 2, 3], label));                // U = string, from the variable's signature
print(map_all([1, 2, 3], (int n) => n * 0.5));   // U = float, from what the lambda returns
print(map_all(["a", "bc"], s => s.size()));      // T = string types s; the arrow's result is U
    output
    [2, 4, 6]
["#1", "#2", "#3"]
[0.5, 1.0, 1.5]
[1, 2]

    The last call passes an arrow that declares no parameter type. Such an arrow is read after the call's other arguments: each parameter it leaves untyped takes the type the signature gives it with what those arguments found (T is string, so s is a string), its body is checked with those types, and its result then names what the signature's result does. An arrow with nothing beside it to type its parameters says nothing, as does an overloaded function's name and a variable declared function. A failure is a load error that says what to write:

    jaiscript
    T pick<T>(T a, T b) { return a; }
T make<T>() { return T(); }

pick(1, 2.5);
make();
    output
    jaiscript: static check failed:
<script>:4:12: error: cannot deduce T for 'pick': it is int from argument 1 and float from argument 2
    pick(1, 2.5);
               ^
<script>:5:6: error: cannot deduce T for 'make': no parameter names it; write make<T>()
    make();
         ^

    The other texts: argument 1's type is not known at load (a var, an untyped host result), argument 1 is null, which says nothing of a type (or is a function, for one that declares no one signature), and argument 1 is int, which 'array<T>' does not match (a signature of another parameter count reads the same: argument 1 is function<int(int)>, which 'function<T()>' does not match). What to write spells the generic's own parameters, with the ones the call did give filled in: for V lookup<K, V>(K key), lookup("hp") ends in write lookup<string, V>(...).

    • A construction has the type it makes, so it deduces like a variable of that type: int(x) and the other primitives, Goblin(), Goblin{}, Box<int>(3), new Goblin() and make_shared<Goblin>() (a shared_ptr<Goblin>), cast<T>(x), a math constructor such as math::vec2(1.0, 2.0), array<int>(3), and a host class's or a host template instance's constructor.
    • A builtin's or a host function's result has the type its declaration states. A builtin method that always gives one type has it (s.substr(1) is a string, xs.contains(x) a bool, names.join(",") a string, xs.back() the element type), on a declared variable and on another such result (s.substr(1).size() is an int); a string's element s[i] is a char; a host function's and a host namespace's is the result it was bound with (to_string(x) and format(...) are strings, thread_count() an int), and a value a host namespace holds has its own type (math::pi is a float); a math value's component (v.x) is a float or an int. An operator over such results, a literal of them, an auto variable declared with one and a lambda that returns one have that type too, so id(to_string(n)) is id<string>. They are types like any other: pick(s.find("l"), 2.5) is the error above, an int beside a float, exactly as pick(1, 2.5) is. A result no declaration states stays unknown, and the call writes its type argument: a method or an element of a var, which holds whatever the program last stored, and a builtin whose result follows its arguments (s.split(","), array::map(xs, f)).
    • A host template deduces like a generic class. For a host that bound Point<int> and Point<float>, T first<T>(Point<T> p) takes either, and T is the argument the instance's name spells (host type arguments).
    • A sized number is a type only as a host template's argument. A host that bound Point<int32> or Point<float32> spells a width no script type has: a script's int and float are 64-bit. Deduced from such a point, T keeps the spelling where it stands as a host template's argument, so Point<T> is still Point<int32> and the instance is first<int32>, and reads as the int or float a value of it is everywhere else: T x;, array<T>, a result, T(). A byte array is the same rule: with array<uint8>, array<T> stays array<uint8> and T alone is an int. No promotion joins the two spellings: same(Point<T> p, T x) called with a Point<int32> and 5 is it is int32 from argument 1 and int from argument 2. The spelling is deduced, never written: first<int32>(p) is unknown type 'int32'. A name the host gave a template's argument that no script type reads as (a class it never bound) deduces where T only stands as that template's argument; a generic that names T anywhere else fails at the call: cannot deduce T for 'first': argument 1 names 'Handle', a type the host binds that no script type reads as.

    Inside an instance​

    Inside an instance a type parameter is its argument. T x;, T(...), T{...}, new T(...), T::member, cast<T>(v), dynamic_cast<T>(v), dynamic_cast<T&>(v), array<T> and a call's f<T>(...) mean what they mean with the argument spelled out, so one text serves a class and a primitive:

    jaiscript
    class Point { int x = 0; int y = 0; Point() {} Point(int a) { x = a; y = a; } }

class Maker<T> {
    static T zero() { return T(); }          // a class default-constructs, a primitive is its zero
    T from(var v) { return T(v); }           // a class's constructor, a primitive's conversion
    T fresh() { T made; return made; }
    array<T> some() { array<T> xs; xs.push(T()); return xs; }
}

print(Maker<int>::zero(), " ", Maker<string>::zero() + "|", " ", Maker<Point>::zero().x);
Maker<int> ints;
Maker<Point> points;
print(ints.from(2.9), " ", points.from(7).y);
print(int(2.9), " ", float(3), " ", string() + "|", " ", bool());
    output
    0 | 0
2 7
2 3.0 | false
    • A primitive constructs by its name. int(), string() and bool{} are the type's zero, and int(x) is cast<int>(x); so are float, char, string and bool. That is what makes T() and T(v) read for every argument.
    • What a type argument may be: int float string bool char, a class, an enum, a math type, array<...>, map<...>, shared_ptr<...>, weak_ptr<...>, function, a signature function<R(A...)>, coroutine<Y>, var, another instance. Never auto, void, a reference (write T& in the generic's own parameter list), a const type (const goes on the variable) or a value: Box<int&>, Box<const int> and Box<3> each fail the load saying which, as a type argument names a type: 'int&' is a reference, not one an instance can be made with; a generic writes T& in its own parameter list. An instance made with a signature or a coroutine type is named as that type is, Box<function<int(int)>>, Box<function<void(Item&,int)>>, Box<coroutine<int>>, and a field that is the parameter holds a callable as a field declared with the type does (a copy of the object rebinds a lambda bound to it). Inside a generic both are types like any other and may name the parameters (function<T(T)> f, coroutine<T> source), and a call deduces through them (Deduction).
    • What the text asks of an argument is the argument's own rule. dynamic_cast<T>(v) with T = int fails as dynamic_cast<int>(v) does, in that instance only; with T = shared_ptr<Hero> it is dynamic_cast<Hero>(v), the handle the argument already names.
    • A type parameter's name is reserved in its generic: a variable, a parameter, a field or a method named T fails the load ('T' is a type parameter of 'Stack': a declaration cannot reuse its name). A member read, x.T, is no use of the parameter. A generic method of a generic class names its own type parameters, never its class's again: class Box<T> { T get<T>(T x) { ... } } fails where it is declared, used or not, with 'T' is a type parameter of 'Box': the generic method 'get' cannot declare it again; give its parameter another name (get<U>), as a member template does in C++.

    One instance, one class​

    An instance's name is its canonical spelling, the one reflect::type_of, reflect::type_name, reflect::classes(), error texts, stack traces and $type in JSON show: Stack<int>, Pair<string, int>, shop::Shelf<shop::Product>. A class argument is named by its qualified name, so the two spellings below are one class. var as an argument is spelled var (Cell<var>). An instance joins its arguments with a comma and a space, a builtin container with a comma alone (Pair<string, int>, Cell<map<string,int>>), and that is the only spelling ever printed or saved. A name that arrives as text is matched without its whitespace: a $type in JSON or in a binary or base64 archive, the class name reflect::construct and the other reflect:: functions take, a name a host looks a class up by. Pair<string,int>, Pair<string, int> and Pair< string , int > reach one class; case stays significant.

    jaiscript
    namespace shop {
    class Product { string title = "tee"; }
    class Shelf<T> { array<T> items; }
    Shelf<Product> inside;                        // Shelf and Product are the namespace's own
}

shop::Shelf<shop::Product> outside;               // the same class, by its qualified spelling
shop::inside.items.push(shop::Product());
outside = shop::inside;
print(reflect::type_of(outside), " ", outside.items.size());

class Cell<T> { T held; }
class Item { int n = 0; }
Cell<Item> a;                                     // a class argument: a copy copies the Item
Cell<Item> b = a;
b.held.n = 5;
Cell<shared_ptr<Item>> c;                         // a shared_ptr argument: a copy shares it
c.held = new Item();
Cell<shared_ptr<Item>> d = c;
d.held.n = 5;
print(a.held.n, " ", c.held.n);
    output
    shop::Shelf<shop::Product> 1
0 5
    • Value semantics follow the argument. A class argument copies with its holder; a shared_ptr argument shares.
    • Statics are per instance, as in C++: Pool<Goblin>::made and Pool<Orc>::made are two variables.
    • Inside its namespace a generic class answers to its bare name, as any class of the namespace does: in the unit that declares it, in another file of the program that opens the namespace, whichever of the two is imported first, and in a later unit that opens it again (namespace shop { Shelf<Product> more; }). Code in a nested namespace reaches its enclosing namespace's generic class the same way, and using shop::Shelf; names it from outside.
    • Two units that use an instance use one class. Each unit declares the instances its own code names (its jaibite is self-contained and no unit waits for another to run); the second declaration of an instance finds it defined from the same generic and does nothing, so its statics keep their values.
    • An instance exists once a unit that ran names it. Loading data does not make one: from_json of a $type that spells an instance no unit used raises 'Cell<float>' names an instance of the generic 'Cell' that the program never made: name the type where it is loaded, as from_json<Cell<float>>(text) does. from_json<Cell<float>>(text) names it (from_binary<Cell<float>>(bytes) for binary, whose error advises that), and so does a variable of the type anywhere in a unit that ran. A $type that cannot name an instance says why in the checker's words for the same spelling: 'Cell<int,int>' names no instance of the generic 'Cell': 'Cell' takes 1 type argument, not 2, unknown type 'Nope' for an argument nothing declares.

    Bounds​

    T : Base requires the argument to be Base or a class that derives from it. A bound is a class and may name the parameters (T : Comparable<T>). It does not change how the body is checked: it moves the error to the use, and says what the generic expects.

    jaiscript
    class Entity { int id = 0; }
class Goblin : Entity { int gold = 3; }
class Orc : Entity { int rage = 9; }

class Pool<T : Entity> {                 // T is Entity or derives from it
    array<shared_ptr<T>> live;
    static int made = 0;                 // one per instance: Pool<Goblin>::made, Pool<Orc>::made
    shared_ptr<T> spawn() { made += 1; live.push(new T()); return live[live.size() - 1]; }
}

int id_of<T : Entity>(T e) { return e.id; }

Pool<Goblin> goblins;
Pool<Orc> orcs;
goblins.spawn();
goblins.spawn();
orcs.spawn();
print(Pool<Goblin>::made, " ", Pool<Orc>::made, " ", id_of(Goblin()), " ", id_of(goblins.live[0]));
    output
    2 1 0 0

    A handle meets a bound its class meets, as dynamic_cast<T> reads one: id_of(goblins.live[0]) and id_of(new Goblin()) are id_of<shared_ptr<Goblin>>, T is the handle, and the body reaches e.id through it as code does anywhere; Pool<shared_ptr<Goblin>> is an instance too. In a bound that names the parameter the handle reads as its class, so shared_ptr<Num> meets T : Comparable<T> where Num : Comparable<Num> does. A weak_ptr meets no bound, since it names no object until it is locked: id_of(w) fails with 'weak_ptr<Goblin>' does not derive from 'Entity', which T requires: a weak_ptr names no object until it is locked; pass w.lock().

    The bound is checked where the instance is asked for, before its body:

    jaiscript
    class Entity { int id = 0; }
class Pool<T : Entity> { array<shared_ptr<T>> live; }

Pool<int> numbers;
    output
    jaiscript: static check failed:
<script>:4:5: error: Pool<int>: 'int' does not derive from 'Entity', which T requires
    Pool<int> numbers;
        ^

    A bound that names no declared class is the same error at each instance asked for, with what is wrong: A<int>: the bound of T, 'Nope', is no declared class: declare it, or bound T by a class that is (T : Base). A parameter bounded by itself, T : T, is an error where the generic is declared, used or not: 'T' is bounded by itself in 'A': a bound names the class T must be or derive from (T : Base).

    Generic methods​

    A method lists type parameters like a function. Its instance is a real method of the class: it reads this, the class's private members and its other methods, and static works as for any method. A generic class may declare generic methods of its own.

    jaiscript
    class CartForm { string sku; int count = 0; }

class Request {
    string body = "{\"sku\": \"tee\", \"count\": 2}";
    T json<T>() { return from_json<T>(body); }      // T forwards to a host's type argument
    static T make<T>() { return T(); }
    T twice<T>(T x) { return x + x; }
}

Request req;
CartForm form = req.json<CartForm>();               // never deducible here: T is only the result
print(form.sku, " x", form.count);
print(Request::make<CartForm>().count, " ", req.twice(4), " ", req.twice("ab"));
    output
    tee x2
0 8 abab

    An instance is listed as a method is, by its bare name with its type arguments: reflect::methods(req) names json<CartForm>, make<CartForm> and twice<int> beside the class's other methods, and that is the name reflect::method_arguments, has_method, invoke and bind take and the name every text about a call gives it: an error the call raises (Cannot call 'json<CartForm>' on null ('req' is null), Cannot pass string to parameter 'x' of 'twice<int>' (declared int), Cannot access private member 'secret<int>' of class 'Vault'), a stack trace's frame (at twice<int>) and the load's own (argument 1 of 'twice<int>': cannot pass 'string' to 'x' declared 'int'). A text about its declaration names the class with it ('A::show<int>' is already defined with parameters (int)).

    A generic method is not virtual (a member template cannot be in C++ either). The instance is chosen by the receiver's class as the load knows it: a variable's declared class, a reference's, the class of another unit's declared global. A derived class's generic of the same name hides the base's, and override on a generic method is an error.

    jaiscript
    class Base { string who<T>() { return "base"; } }
class Derived : Base { string who<T>() { return "derived"; } }

Derived d;
Base& as_base = d;
print(d.who<int>(), " ", as_base.who<int>());
    output
    derived base

    A receiver whose class the load does not know (a var) cannot pick an instance: cannot instantiate 'json<CartForm>': the receiver's class is not known at load. Give it a typed variable or a typed reference. A call that leaves its type arguments to deduction loads, since a var may hold any class, and fails where it runs with the same advice: Base::twice is a generic method: its instance is picked where the call is written, from the receiver's class, which is not known there; give the receiver a typed name (Base x = ...) or cast it (cast<Base&>(x).twice(...)).

    The class may stand below the call. A function above the class, or above the import that brings it, may call its generic method: the method's instance is declared the moment its class is (When an instance is declared). A call that runs before then finds no class, as a call of a plain method would: Class 'Oracle' not found for a static call, No constructor found for class 'Oracle' where it would make one. A class declared again keeps the instances its callers declared.

    jaiscript
    int ask(Oracle o) { return o.answer<int>(3); }      // above the class: its instance waits for it

class Oracle {
    int base = 4;
    T answer<T>(T x) { return x + base; }
}

print(ask(Oracle()));
    output
    7

    When an instance is declared​

    An instance is declared the moment everything it is built on is declared: its generic, every class its type arguments name, its base classes, and for a generic method's instance the class it belongs to. When all of those exist as the unit starts (they came from imports that already ran, or are builtin types), that moment is the start of the unit. No place is computed from the uses, so it does not matter how the instance is first named: a type, a construction, a call, a cast, a dynamic_cast, a type argument, a function's or a lambda's body, another instance's text.

    jaiscript
    int seed() { return 5; }
class Shelf<T> {
    static int made = seed();          // runs when the instance is declared
    T item;
}
print(reflect::classes().contains("Shelf<Book>"));    // Book is not declared yet: Shelf<Book> waits for it
class Book { string title = "Dune"; }
print(reflect::classes().contains("Shelf<Book>"), " ", Shelf<int>::made);
auto shelf = Shelf<Book>();              // an expression names it first; the type below changes nothing
Shelf<Book> other;
print(shelf.item.title, " ", other.item.title);
    output
    false
true 5
Dune Dune
    • Its declaration runs at that moment, as a class written at that point would: the initializer of a static runs then and sees what is declared above it (seed above), a base class is looked up then, and nothing declared further down exists yet. A static's initializer that reads a global declared below the generic fails as it would in a plain class there.
    • The order rule is the one plain names have. A use in top-level code names the generic and its argument classes, so it stands below their declarations: above one, a construction or a call is a load error with the plain text ('Box' is used before its declaration (line 3): ..., 'Item' is used before its declaration (line 4): ..., 'twice' is called before its declaration (line 2): ...), and a typed declaration is a run-time error, as it is for a plain class, that says what the instance waits for ('Holder<int>' is not declared yet: it waits for 'Holder' where the plain class is No constructor found for class 'Plain'). A function's instance is declared the moment its generic is: a function above the generic may call it, and a call that runs before the generic's declaration has run fails where a call of a plain function declared below does, with 'twice<int>' is not declared yet: it waits for 'twice' where the plain one is Undefined variable 'twice'.
    • A class may derive from an instance of itself, class Num : Comparable<Num>: the instance is declared as that class's declaration begins.
    • An instance that still waits says what for, whatever reaches it: a typed declaration, a construction, new or a container's element in a function that runs above class Book, reflect::construct("Shelf<Book>") and from_json of that $type all raise 'Shelf<Book>' is not declared yet: it waits for 'Book'. The text is the same on both backends.

    Errors in an instance​

    An error inside an instance is reported at the generic's own file and line, with a note that names the instance and where it was asked for; nested instances add one note per level. Each instance reports what its own arguments break, and an instance that is sound reports nothing:

    jaiscript
    class Box<T> {
    T item;
    int length() { return item.size(); }
}

Box<string> words;
Box<int> count;
    output
    jaiscript: static check failed:
<script>:3:32: error: int has no member 'size'
    in Box<int>, instantiated at <script>:7:4
        int length() { return item.size(); }
                                   ^

    Modules, hot reload and jaibite​

    A generic is visible to every unit of the program, like a function: the units a root reaches through import and include are gathered before any is checked, and a unit that ran earlier in the engine counts too.

    jaiscript
    import "stack.jai";

Stack<string> names;
names.push("ann");
print(names.items.size(), " ", Stack<string>::made, " ", reflect::type_name(names));
print(to_json(names));

    with stack.jai:

    jaiscript
    class Stack<T> {
    array<T> items;
    static int made = 0;
    Stack() { made += 1; }
    void push(T item) { items.push(item); }
}
    output
    1 1 Stack<string>
{"$type":"Stack<string>","$val":{"items":["ann"]}}
    • Hot reload. A generic's file is part of every module that instantiates it, as a template file is part of the module that renders it: an edit to the generic re-runs those modules (their classes and functions replace the old ones in place, their top-level statements run again). A broken edit is reported and the old code keeps running: an edit that an instance some loaded unit names cannot be made from rejects the reload, whether or not that unit runs again, and nothing of the edit is applied (Declaring it again).
    • jaibite. A unit's jaibite holds the instances it uses as ordinary declarations, and a generic as its tokens, so a loaded generic still instantiates. An instance of a generic another unit declares follows the engine that runs the bite: made again from the declaration that engine holds when it differs from the one the bite was saved with. A unit that instantiates a generic another file declares keeps no jaibite cache, like a unit with a spliced include: its freshness would know only its own file.
    • Declaring it again. An edit to a generic's file is the generic declared again: the instances the engine holds are made again as the file runs, and each module that runs again finds its instances made and resets nothing (Declaring it again).

    Declaring it again​

    A generic's name is declared, declared again and clashes as a class's name does. A later unit that declares it (a later execute, its file loaded again after an edit, another file) replaces the earlier declaration, and nothing asks for the engine to start over.

    Every instance the engine holds is made again from the new text, where the new declaration stands, whatever the unit names. An object that lives takes the new methods and gains the new fields, a function compiled before the change calls the new body, and a field or a static that keeps its name keeps its value: what a class declared again does.

    jaiscript
    class Box<T> { T v; static int made = 0; Box() { made += 1; } int get() { return 1; } }
Box<int> a;
a.v = 5;
int use() { Box<int> x; return x.get(); }
print(a.get(), " ", use());
import "again.jai";                 // another unit declares Box again and names no instance
print(a.get(), " ", use(), " ", a.v, " ", Box<int>::made);

    with again.jai:

    jaiscript
    class Box<T> { T v; int extra = 7; static int made = 0; Box() { made += 1; } int get() { return 3 + extra; } }
    output
    1 1
10 10 5 3
    • Top-level code runs in order: above the new declaration the earlier instance still answers, below it the new one, as with a class declared twice in a unit.
    • A generic function and a generic method follow the same rule: the instances their callers hold are made again when the generic is declared again (a method's when its class is). A generic function declared with other value parameters is another overload beside the first, as for a plain function, and the first one's instances stay. An instance belongs to the declaration it was made from: of two overloads that both made show<int>, the one declared again makes its own show<int> again and leaves the other's.
    • An instance the new declaration cannot make (another count of type parameters, a bound its argument no longer meets, a body that does not check for its arguments) gets the verdict a function gets when a caller no longer fits it. A reload, a module's file imported again after an edit or a file the host runs again with execute_file, checks every loaded unit before anything runs: an instance one of them names rejects the reload with the error that instance has (Errors in an instance), nothing is applied, and every instance and function of the file keeps the code it had. A reload reads the file as it stands, so a generic function it no longer declares with those parameters, and a name it gives to a class or a function, reject the same way; a generic the file drops altogether stays, as a function or a class a file drops does: its users run on, a unit that runs again or is edited still names its instances and may make new ones, and the next declaration of the name replaces it. Declared again by text that loads without a reload, which checks no unit but itself (a later execute, another file's first load), and in a reload when no loaded unit names it, the instance keeps the declaration it has, and the unit's check warns, naming it and the reason: 'Box<int>' keeps its earlier declaration: this declaration of 'Box' cannot make it: 'Box' takes 2 type arguments, not 1. The objects of that instance keep working; naming it in new code is the ordinary error for the same reason, and a later declaration that can make it does. [[warn_mode]] does not change this: every load is checked, a host has no switch that turns the check off, and under [[warn_mode]] an instance the unit's own text names is made with its errors reported as warnings, like the unit's other errors, while an instance the unit only makes again still keeps its earlier declaration.
    • One name is one class. class Box<T> beside class Box in one unit fails the load at the second of them: class 'Box' is declared without type parameters on line 1 and with 1 type parameter here: a class and a generic class cannot share a name. From a later unit the later declaration takes the name. A class declared under a generic class's name is a declaration that cannot make that generic's instances, with the verdict above: a reload a loaded unit names one in is rejected, and otherwise they stay as they are, with the warning (... cannot make it: 'Box' takes no type arguments: it is not a generic class). A generic class declared under a class's name leaves the class to the code and the objects that use it already, and the bare name then names no class wherever a class's name can stand in new code: a declared type (a variable's, a parameter's, a result's, a field's, a handle's or a container's element), a type argument, new, cast, dynamic_cast, a base class, a braced construction Box{}, a static member Box::made and the name as a value. Each is 'Box' is a generic class: name its type arguments (Box<T>), the error a bare generic name gives anywhere; a namespace's generic class gives it by its qualified name too (shop::Box::made).
    • Two files that each declare a generic class of one name do what two files that declare one class do: the one that runs later replaces the other. Two files that each declare a generic function, or a class's generic method, with the same value parameters do what two files that declare one function do: every caller, in either file or a third, reaches the one that ran later, and a file declared again after an edit takes over at once. Generic functions that differ in their value parameters stay overloads, whichever files declare them. In a namespace a function collides across files instead of replacing, and a generic function with it: the second file's declaration of the same name and value parameters raises Function 'f' already exists in namespace 'n'. Use 'override' keyword to replace it. where it runs, the first stands for every caller, and a declaration written override (string f<T>(T x) override { ... }) replaces it. A file run again replaces its own.
    • A unit that made instances again keeps no jaibite cache: what it declared rested on what the engine held. A bite a host saves from such a unit (engine::jaibite, then save or save_bytes) carries the instances its own text names and none it only made again: the engine that loads it makes again the instances it holds itself, and a fresh engine declares the generic alone.

    Limits and what is not here​

    • Instantiation is limited in everything that can grow, and passing a limit is a load error with the first links of the chain, not a hang. It nests at most 64 deep: class A<T> { A<array<T>> next; } fails the load with generic instantiation nests more than 64 deep. An instance's name is at most 4,096 characters: class Grow<T> { Grow<Pair<T, T>> next; }, whose instances double at every level, fails with generic instantiation names an instance of more than 4096 characters. One use in the program's own text makes at most 4,096 instances, those its instances' text names counted: void walk<T>(int n) { walk<L<T>>(n - 1); walk<R<T>>(n - 1); }, whose every instance asks for two more, fails with generic instantiation makes more than 4096 instances from one use. The count is each use's own, so a program names as many instances as it likes. A use that passes a limit reports that one error, and nothing more is made for it. A note under an error spells an instance's name of more than 80 characters by its two ends (in A<array<array<arra ... >>>>, instantiated at ...).
    • A class's members are made with it, so that an instance is the class as written by hand, to reflection and to a var receiver alike. A member that names an instance of its own generic built from the instance itself would therefore ask without end, and fails the load at the first step, where the member stands: for class List<T> { List<List<T>> chunks() { ... } }, List<int> reports 'List<int>' would need 'List<List<int>>' and so on without end: the member 'chunks' names an instance of 'List' built from the instance itself; a class's members are made with it and a generic function only where it is called, so write it as one outside the class: chunks<T>(List<T> self). The generic function it names, List<List<T>> chunks<T>(List<T> self), is made only for the calls the program writes.
    • Each of these is a load error with its own text, not a silent gap: default type arguments (<T = int>), specialization (class Stack<int>), non-type parameters (<int N>), variadic parameters (<T...>), generic lambdas (use auto parameters), deducing a class's arguments from its constructor, an instance as a function value, a generic declared inside a function body, and a generic constructor or operator (Box<T>(T x), operator+<T>(T x): a constructor takes no type parameters: give the class them (class Box<T>), or declare a constructor for each type it takes, and the same of an operator). A generic class's constructor is spelled by the bare name, Pair(K k, V v); Pair<K, V>(...) there is a constructor is named by its class's bare name: write Pair(...); inside the class, Pair is Pair<K, V>.
    • Type arguments go on a generic's name only. On any other type they fail the load once, wherever the type stands, with what the name is: 'Hero' takes no type arguments: it is not a generic class, ... it is a host class, not a host template, ... it is an enum, 'int' takes no type arguments: it is a builtin type. A generic's own type parameter takes none either, and that is an error where the generic is declared, used or not: 'T' takes no type arguments: it is a type parameter of 'List'.
    • A generic class or function may not take the name of a template the host bound (host type arguments), since Point<int> spells the host's class: 'Point' is a host template: a generic cannot take its name. A generic class may not take the name of a class the host bound, as no script class may: cannot declare class 'Sprite': the host binds a C++ class of that name; give the script class another name, or derive from it (class Other : Sprite). A generic function may, as a plain function may, and a generic method's name is its class's own.
