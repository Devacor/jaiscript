    Reference​

    The lookup page. The guide teaches the language and the embedding chapters teach the host API; this page is where you come back to when you already know the shape of a thing and need the exact rule, the exact spelling, or the exact error text. The tables point back at the chapters that show each rule running, and the Documents section at the end indexes the specification files themselves.

    Two conventions, used everywhere below. A handle is a shared_ptr<T>; a reference is a T&. And the checker means the static checker that runs before any script executes. It is on, in strict mode, unless the host turns it down.

    Overflowing + - *, unary -, and INT64_MIN / -1 raise a catchable runtime error in the default build (JAISCRIPT_CHECKED_OVERFLOW). Integer arithmetic is never undefined behavior. Integer and float division by zero raise a catchable error (no IEEE infinity). When you want wraparound on purpose, math::wrap_add / wrap_sub / wrap_mul say so.

    char operands promote to int (unsigned, 0..255) under arithmetic, bitwise, and comparison operators: 'a' == 97 is true, 'z' - 'a' is 25, and s[i] > 127 is an unsigned high-bit test (byte 0xC3 is 195, never -61). There is no implicit int→char: type_of('a' + 1) is "int". A char converts only through an explicit cast: cast<char>(n) (range-checked 0..255), cast<int>(c), cast<string>(c), cast<char>("a"), or through the stdlib function form to_char(n), or a \xNN literal.

    Overloading on script classes. A class declares C++'s overloadable set less && || , -> new delete and !: binary + - * / % & | ^ << >> < > <= >= == != <=>, unary - + ~ (told apart from the binary form by the parameter count), =, [] and (), each as a method (Vec operator+(Vec o)). Truthiness is bool to_bool(): if (v) calls it and !v negates it, and declaring operator! is the parse error operator! cannot be declared: !v is !to_bool(v); declare bool to_bool(). operator() makes an instance callable (v(1, 2)); the checker still holds a function slot to functions and null, so a callable instance goes in wrapped in a lambda. Words from other languages (goto, virtual, delete, constexpr, ...) are not reserved; where one would fail to parse, the error names the JaiScript spelling (the table below).

    Type conversions​

    An example before the table. Every one of these is the same rule applied to a different slot:

    jaiscript
    class Meters { float v = 0; Meters(float x) { v = x; } }
class Reading { int raw = 0; Reading(int r) { raw = r; } int to_int() { return raw * 10; } }
Meters m = 3;              // one-step converting constructor
int n = Reading(4);        // to_int() on the way into an int slot
float f = 7;               // widens
int t = 3.99;              // truncates toward zero
bool b = 5;                // truthiness
string s = to_string(42);  // text only: stringify explicitly
print("{} {} {} {} {} {}", m.v, n, f, t, b, s);
var nul = null;
Meters typed_null = nul;   // null is a typed null in any object slot
print("{}", typed_null == null);
    output
    3.0 40 7.0 3 true 42
true

    (A float prints as the shortest text that reads back to the same value, keeping .0 on a whole number, with inf, -inf and nan for the values no digits spell (every NaN prints nan, a format spec included, whatever produced it); template strings and {} placeholders take format specs: ${f:.1f}.)

The same conversion rules govern declarations (int x = e), assignment (x = e), by-value parameters, return values, instance and static field stores, and the element boundary of typed arrays and maps. A conversion is always one step: a converting constructor or a to_X() method runs, but never chains (X.to_int() followed by C(int) is not implicit).

    When a mismatch is caught. If both sides are visibly typed (int x = "s", a string returned from a function declared -> int, an unrelated class into a typed field), the checker reports it and the load fails before a single statement runs. If the value came through var (or any other slot the checker treats leniently), the same rule runs at run time and raises a catchable error with the texts in Diagnostics. Both cases are the same table; only the moment differs.

    Compound assignment. On a typed (or locked-auto) target, a op= b computes like C++ and converts the result back to the target's type (int i = 7; i /= 2 → 3; i += 0.5 → 7; i += "s" is an error). On a var target the stored value is whatever the operation produces. A compound reads its target first, so on a missing map key it raises (map<string, int> m; m["x"] += 5 raises Key "x" not found in map). The value of an assignment expression is what the destination stored (auto r = (i = 3.9) is int 3).

    The typed boundary and the escape hatches​

    Three spellings let you say, precisely, where you are stepping outside what the checker can see. None of them loosens anything else.

    cast<T>(e), cast<T&>(e), cast<shared_ptr<T>>(e)​

    jaiscript
    class Base { int b = 1; }
class Derived : Base { int t = 0; }
class Holder { Base p = Derived(); }     // a Derived, held through a Base-typed field

print("{} {} {}", cast<int>('a'), cast<char>(97), cast<string>('z'));
char c = cast<char>(65);                 // `char c = 65;` would be a load error

auto h = Holder();
cast<Derived&>(h.p).t = 5;               // alias the same object: the store lands
print("{} {}", c, cast<Derived&>(h.p).t);

shared_ptr<Derived> sp = new Derived();
shared_ptr<Base> sb = cast<shared_ptr<Base>>(sp);   // share it, don't copy it
sb.b = 42;
print("{}", sp.b);

var v = Base();
try { Derived d = cast<Derived>(v); } catch (e) { print("caught: {}", e); }
    output
    97 a z
A 5
42
caught: Cannot cast 'Base' to 'Derived'

    The operand is never checked against T statically. That is the point of a cast. A class mismatch raises the catchable Cannot cast 'X' to 'T' where X is the object's run-time class; null passes the value and handle forms (you get a typed null) and fails the reference form (Cannot cast 'null' to 'T&'). A T that names no class is a load error. Chapter: The Type Ladder.

    extern​

    extern declares a name that exists outside the program (a host global bound after load, a function the running instance registers, a value another engine injects) so that the checker counts it as declared instead of reporting use of undeclared identifier. At run time it declares nothing: the name resolves when it is used, and a use while nothing defines it raises 'name' is declared extern but never defined (an 'inline' declaration creates it) (extern function: without the parenthesis). inline T name; is the C++17 inline variable: one variable shared by every unit that declares it, created with its initializer or its type's default by the first to run and adopted by the rest (a later unit's initializer does not run again). Inline and plain declarations of one name never mix: a plain declaration of an inline variable raises 'x' is already defined inline; declare it 'inline int x;' to share it, and an inline declaration of another unit's plain variable raises 'x' is already defined (not inline) in <file>; declare every definition 'inline' to share it. When the checker sees both units it reports the plain declaration at load, with the first text.

    using ns::name; (a comma list: using game::spawn, game::cost;) makes the rest of the file read name as ns::name, for any namespace. It is a parse-time rewrite: file-local, not transitive through imports or includes, and the name cannot be declared again in that file. There is no using namespace.

    SpellingMeaning to the checker
    extern function log_to_host;a callable of unknown signature: calls are unchecked
    extern int frame; / extern shared_ptr<Game> G;typed: member access, assignments and conversions are checked exactly as for a declared variable of that type
    extern config;untyped: behaves like var
    extern function game::spawn; / extern int a::b::depth;a namespace member, in any of the three strengths: the namespace declares it, so game::spawn is not no member 'spawn' in namespace 'game', and the path opens the namespace for its other members' checks

    An extern stands at program scope or in a namespace, where its name is the namespace's: namespace game { extern int tick; } declares game::tick, which the namespace's own blocks read as tick, and namespace game { extern ai::depth; } declares game::ai::depth. A use of a qualified extern while nothing defines it raises the same text with the qualified name, 'game::tick' is declared extern but never defined (an 'inline' declaration creates it); the definition is a namespace block of any unit (namespace game { int tick = 0; }) or the host's registration of that namespace.

    An extern name travels with the program: every unit the root imports sees it. It is also the idiom for a shared leaf that reaches into a module only some programs import. In a program that does import the module, the declaration is inert and the real definition wins.

    [[warn_mode]] and [[strict_mode]]​

    jaiscript
    extern function log_to_host;   // the host registers this later: calls are unchecked
extern int frame;              // typed: reads and stores are checked as an int
extern config;                 // untyped: behaves like var

int total = 0;
try {
    [[warn_mode]] total = "oops";        // this one statement is only warned about...
} catch (e) {
    print("run time: {}", e);            // ...so the mistake surfaces here instead
}
print("{}", total);
    output
    run time: Cannot assign string to 'total' (declared int)
0

    The two attributes set the checker's mode for a region of one file. They compose and the innermost wins; everywhere else a file is strict. Where the attribute sits decides what it covers:

    PositionCovers
    first declaration of a file ([[warn_mode]]; at the top; a leading comment is fine)the whole unit
    first statement of a block (a function, method or lambda body, an if/while/for body, a bare { })the whole block, nested bodies included
    before any other statementthat one statement's own subtree; a nested function or lambda body inside it keeps the enclosing mode

    In a warn region every error is reported as a warning (still collected, still visible through engine->check()) and an undeclared identifier is accepted as unknown; nothing is proven from it. In a strict region errors gate the load, even inside a warn region. The runtime never changes: both backends treat the attribute as nothing, so a warn region's type mistakes raise at run time exactly as they would have without a checker, which is what the example shows. A unit's mode says nothing about the units it imports. The one other attribute is [[nodiscard]], which marks a function or a method whose result a caller must use (Functions); any other name is a parse error.

    Diagnostics as you read them​

    There are two shapes of error, and knowing which one you are looking at tells you when it happened.

    The static listing (before anything runs)​

    jaiscript
    int x = 5;
x = "hello";                  // typed to typed: the load fails, nothing runs
print("never printed");

    The shape is FILE:LINE:COL: error: MESSAGE, then the source line, then a caret. FILE is the unit's resolved path for a file (the root file, an import, an include) and <script> for source text handed to execute(). Messages are lowercase, except the few that reuse a run-time text and keep its capital (Cannot access private member 'x' of class 'C', Cannot access private constructor of class 'C'); a message about a declared name ends with that declaration's position, (declared at LINE:COL). A failed load hands the host one jai::static_check_error whose what() is the whole listing (sorted by location, deduplicated, capped at 100), and nothing has executed. Warnings (shadowing, a copying cast) use the same shape with warning: and never stop the load. A syntax error reads the same way under parse failed: instead, thrown as jai::parse_error: the parser lists every syntax error it meets in source order (it resumes after each), and no check runs until the source parses.     Command-line runner​

    jaiscript is the reference embedding and the quickest way to run anything on this site. It is built by the jaiscript_runner target (on by default), lands in build/bin/, and always registers the full stdlib, the web:: library, the spider:: HTTP client (WinHTTP on Windows, sockets elsewhere, the network permission granted), file IO (read_file, write_file, file_exists, delete_file, move_file, dir_exists, make_dirs, list_dir, writable_dir, plus Download, zip_entries and zip_extract), a small console-game surface (read_key, key_down, term_cols, term_rows, env_var, and sound: load_sound, play_sound, stop_sounds; clocks are the standard library's time::), two socket classes, NetServer and NetChannel, and net_host_name and net_local_addresses. Enough that the example shims and JaiDoom run on it unmodified. Full notes: tools/jaiscript/README.md.

    InvocationWhat happens
    jaiscript file.jai [-- args...]run the file as a suspendable run (each sleep returns to the runner, which waits on the engine's clock and resumes it) and exit; the exit code is the script's trailing int expression if there is one, 1 on a script error, 2 on a usage error (an unknown flag, a missing or malformed value). Only 0 to 255 survive as an exit code everywhere: an int outside that range exits with its low byte (300 exits 44, -1 exits 255) on every platform. Everything after -- is the global ARGS. Dropping a .jai onto the executable does the same and pauses before closing
    jaiscript -e "source" [-e ...] [-- args...]run the source text and exit, as a file run runs a file's text: several -e run in order in one engine (declarations carry over, the first error stops the run), the exit code is the last source's int result, 1 on a script error. Nothing prints unless the source prints (jaiscript -e "print(1 + 2)"); the REPL is the mode that echoes values (echo 1 + 2 | jaiscript). Combines with the flags below; include/import resolve from the working directory; a script file or --watch alongside is a usage error
    jaiscripta REPL with a persistent engine: :load, :reset, :backend vm|interp|vm-reference, :time on|off, :help, :quit. Piped input (echo 1 + 2 | jaiscript) exits 1 when any input failed, else 0
    jaiscript --watch file.jaire-run the file on every save, in a fresh engine each time (a program that keeps its world reloads with a guarded import in its loop instead: Reloading from a running program)
    FlagMeaning
    --backend=vm|interp|vm-referenceexecution backend (default vm); both must agree, so the other one is your second opinion. vm-reference is the VM with every optimization off (engine::vm_reference_mode)
    --warningslist the checker's warnings on stderr before the script runs (typed mistakes and undeclared names always fail the load)
    --workers=Nthe worker count of parallel_for, parallel_transform and parallel_reduce (default: the engine's own)
    --budget=Nexecution budget in seconds per execute; default 0 = unlimited (the embedded default of 5.0 s is deliberately lifted in a runner)
    --timeprint wall time per run
    --debug / --debug-port=Nstand up the DAP debug listener on localhost (VS Code attaches to it) and name the port it bound on stderr; --debug-port=N listens too, trying port N first (default 52477, probing upward in steps of 10). Without either, nothing listens
    --pause / --no-pauseforce or suppress the "press Enter to close" hold after a file run
    --version / --help
    --benchmark-main=Nrun the file once as a warm-up, then call its main() N times (a repeatable timing loop)
    --no-param-alias / --no-local-aliasturn off the read-only copy elision for by-value parameters / locals, so every one copies (results never change; a tool for measuring and for bisecting)
    --no-proofsrun without type proofs, typed ops or cell blocks: the general form, with the same results
    --miss-every=Nthe VM misses at every Nth plain cell instruction, exercising the flush at every position (a build configured with JAISCRIPT_MISS_INJECTION)
    --disasm=FILE / --manifest=FILEwrite every chunk the VM compiles to FILE: readable listings, or exact semantic manifests
    --coverage=FILEthe VM's execution-coverage census at exit (a build configured with JAISCRIPT_VM_COVERAGE)
    --selftestrun the runner's built-in smoke tests and exit

    Ctrl+C. Ctrl+C or Ctrl+Break on Windows, and SIGINT, SIGTERM or SIGHUP on Linux and macOS, end the runner at once, in every mode the REPL included: the script stops where it is, without running its destructors, and the exit code is 130 (on Linux and macOS the signal itself ends the process, so the shell reports 130, 143 or 129). A signal the runner was started with ignored (nohup, a background job) stays ignored. Before it exits the runner gives the terminal back, following what the script printed: on a terminal it resets the colours, shows the cursor and leaves the alternate screen only where the script changed them, and it does the same when a script ends or fails without undoing them; the input mode, and on Windows the console mode and code pages, come back too. A pipe or a file receives none of it. A script that must stop itself in time has the execution budget (--budget=N).

    The runner's host API​

    The runner registers these on every engine it builds; a host embedding JaiScript has none of them unless it registers its own. The calls that name a file (the file functions, Download.start, load_sound and play_sound) run under the engine's filesystem privilege, so an engine with it disabled raises Insufficient privilege: filesystem. at the call; Download.start reaches the network too and needs the network privilege as well. Signatures and effects are also in the API reference under the standalone runner. Locations (executable_dir(), root_script_dir(), current_script_dir(), resolve_path(name), app_data_dir(name) and the rest) are language builtins on every engine, described in Modules; a script that builds its paths from them runs the same from any working directory.

    Files and foldersBehavior
    read_file(path) -> stringthe file's bytes exactly (binary mode; "" for an empty file). A file that is missing or unreadable raises Cannot read file '<path>': <reason>
    write_file(path, text) -> boolwrites the bytes exactly, creating missing folders; false when it cannot
    file_exists(path), dir_exists(path) -> boolwhether the path names something, or a folder
    delete_file(path) -> boolremoves the file; false when nothing was removed
    move_file(from, to) -> boolreplaces to; false when from is not a file. On one volume the replacement is a single operation, so a reader sees the old file or the new one (the last step of a safe save: write save.tmp, then move it over save.txt); across volumes it copies, then removes the source
    make_dirs(path) -> boolcreates the folder and its parents; true when the folder exists afterwards
    list_dir(path) -> array<string>the folder's entry names, sorted; empty for a folder that cannot be read
    writable_dir(path) -> boolcreates the folder if missing, then writes and removes a probe file: whether the folder can take a save
    zip_entries(zip) -> array<string>, zip_extract(zip, entry, dest) -> boola zip archive's entry names, and one entry written to dest with its CRC-32 verified
    Download()an asynchronous download the script polls from its own loop: start(url, path) begins it (http or https; false with error() set when it cannot begin), pump() returns true once it is done, success() and error() give the outcome, received(), total() (-1 until known) and fraction() the progress, cancel() stops it. A failed transfer leaves no partial file
    Console gamesBehavior
    read_key() -> stringthe next key press, without waiting: "" when none is queued, else "up", "down", "left", "right", "enter", "esc", "tab", "space", "backspace", a lowercase letter, a digit or a punctuation character (on Windows also "shift", "ctrl" and "alt")
    key_down(name) -> boolwhether the named key is held now: a letter, a digit, "space", an arrow, "enter", "esc", "tab", and on Windows "shift", "ctrl" and "alt". A POSIX terminal sends no key releases, so there a key reads as held for half a second after its last press or auto-repeat, and the modifiers never read as held
    term_cols(), term_rows() -> intthe console window's size in characters (80 by 25 when it cannot be read)
    env_var(name) -> stringan environment variable's value, "" when it is unset: env_var("COLORTERM") is "truecolor" or "24bit" in a terminal that takes 24-bit colour
    SoundBehavior
    load_sound(path) -> Soundopens a WAV, MIDI or MP3 file and returns at once while the file preloads in the background, so a long song is ready by the time it plays. The file's first bytes name the format (RIFF/WAVE, MThd, an ID3 tag or an MPEG frame); a header it does not recognize falls back to the extension (.wav, .mid, .midi, .mp3). null for a missing file or another format
    s.play(), s.play(true) -> boolstarts the sound from the beginning, looping forever with true, and returns at once; playing a Sound that is already playing restarts it. false once the file proved unplayable (its data did not decode)
    s.stop(), s.playing() -> boolstops it; playing() is true from play() until stop(), stop_sounds() or the end of a sound played once
    s.volume(level)sets the level, 0.0 to 1.0 (clamped); a Sound starts at 1.0
    s.format() -> string"wav", "midi" or "mp3"
    play_sound(path), play_sound(path, true) -> Soundload_sound then play, for a sound fired and forgotten: it plays to its end (or forever, looped) even when the result is dropped, and the result stops it. null as load_sound
    stop_sounds()stops every Sound

    Every Sound is its own voice: music in one, ambience in another and effects in the rest all play at once, mixed. A Sound loaded once and played again is the way to fire an effect many times, since loading a file costs more than playing it. A loaded Sound closes when the last variable holding it lets go (a copy of a Sound is the same sound). No call waits on the audio device: one audio thread opens and drives the devices, so a frame loop never stalls on a sound. Sound plays on Windows; elsewhere load_sound and play_sound return null, so a script that checks for null, as it does for a missing file, runs unchanged, silent.

    jaiscript
    var music = load_sound("theme.mid");
var hit = load_sound("hit.wav");
if (music != null) { music.volume(0.6); music.play(true); }   // loops until stopped
if (hit != null) { hit.play(); }                               // again and again, each restarting it
play_sound("door.wav");                                        // fire and forget
    NetworkingBehavior
    NetChannel()one framed TCP connection: listen(port) waits for one peer, connect(host, port) dials one, send(bytes) queues a packet, pump() moves the bytes and fires the signals, close() drops the connection; connected() and status() ("idle", "listening", "connecting", "connected", "closed: <reason>", "error: <reason>") report its state
    NetServer()many framed TCP clients on one port: listen(port), send(id, bytes), broadcast(bytes) (the count of clients it reached), pump(), kick(id), client_count(), listening(), close(). Client ids count up from 1 and are never reused by one server
    net_host_name() -> string, net_local_addresses() -> array<string>this machine's name and its IPv4 addresses, loopback left out: what a player hosting a game tells the others to type

    A packet is one send's bytes, delivered whole and in order: on the wire each packet is a 4-byte big-endian length, then the bytes. Neither class runs a thread. The sockets do not block, and the signals fire only inside pump(), on the script's own call stack, so a game calls pump() once a frame. A NetChannel fires on_connect(), on_packet(bytes) and on_disconnect(reason); a NetServer fires on_client_connect(id), on_client_packet(id, bytes) and on_client_disconnect(id, reason). A disconnect's reason is "closed by peer", "recv error", "send error", "oversized frame" (a length over 64 MiB) or, for a server's client, "kicked". Packets that arrived ahead of a close are delivered before its disconnect.

    NetChannel.connect is asynchronous. It returns false only when the attempt fails at once (the host name does not resolve, the socket cannot be made), with the reason in status(). Otherwise it returns true while the connection is still being made, and the outcome arrives later through pump(): on_connect() when the peer accepts, on_disconnect("connect refused") when it does not. Packets sent before then wait in the queue and go out once the connection is made.
